# 动作迁移

一个独立作品是一个项目，每组动作迁移输入创建一个项目和一个 RunningHub 任务。批量提交三组会创建三个项目；批次只负责幂等入队与汇总。task_get 返回 projectId，重试仍属于原任务和原项目，不能用重新创建代替重试。

加载本技能后，Atelier 工具仅在当前回合开放。下一回合需要查询、取消或继续操作时再次加载本技能，不因历史技能正文仍在上下文中而跳过加载。

1. 先调用 atelier_capabilities 检查 hasApiKey 并查询当前工作流和参数。若 hasApiKey 为 false，先提示用户：“请先在 Atelier → 服务设置中配置 RunningHub API Key，保存后告诉我继续。”此时不创建或重试生成任务，不要求用户在聊天中粘贴密钥。用户配置后重新调用 atelier_capabilities，确认 hasApiKey 为 true 再继续；字段缺失或查询失败不能视为已配置，应提示检查后端连接。历史任务查询不受此配置检查阻挡。随后调用 atelier_asset_list 同步当前会话附件并查询全局素材库。素材可跨会话复用，当前会话没有附件不代表用户引用的素材不可用。
2. 优先使用用户本条消息中明确选定的 Atelier 素材 ID 或原生附件。按 ID 在全局列表中匹配类型和名称，匹配成功无需再次上传或复制文件。素材列表可能包含历史附件和生成结果，不能默认把所有图片组成批次或随意选择历史视频。引用不存在或无法唯一对应时询问用户。
3. 用户明确提供本机路径时可以调用 atelier_asset_import。缺少人物图或参考视频时追问，不创建占位任务。
4. 人物图、视频及必要参数齐全后调用 atelier_task_create，无需再次确认计划。使用稳定 requestId，网络重放沿用相同标识。仅填写业务参数，不构造平台节点或索取密钥。
5. 入队后返回任务 ID 和本地状态，不循环查询，不等待生成完成。后台独立保存结果和通知。
6. 只有用户明确要求才取消或重试。submission_unknown 必须先核对，不能通过重新创建绕过。查询当前会话任务可用 atelier_task_list、atelier_task_get。

当前能力仅支持 Wan Animate2 单段动作迁移及多个明确指定的单段任务。默认 480×848、读取全部帧、跳过 0 帧，固定 30fps；用户参数覆盖默认值，最终以服务校验为准。

## 动作迁移实例选择

- 未明确指定实例时，480×848 及相近尺寸为【普通】清晰度，使用普通实例，RunningHub 创建请求省略 `instanceType`；720×1280 及相近尺寸为【高清】清晰度，发送 `instanceType: "plus"`。
- 相近尺寸按总像素量更接近上述哪一档判断，横竖屏一致：超过 664320 像素使用 plus，否则使用普通实例。该阈值是本插件的默认选择规则，不是平台限制。
- 工具的 `parameters.instanceType` 可以省略，由后端落实默认规则。用户明确指定 plus 时传 `"plus"`；明确要求普通实例或不传平台参数时传 `"default"`，后端会省略平台字段，即使尺寸为高清也不覆盖用户选择。
- 规则仅用于动作迁移，不推断其他工作流的实例需求。实例选择不改变用户要求的尺寸。

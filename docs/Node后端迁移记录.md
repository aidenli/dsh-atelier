## 实现与模块

| 模块 | 职责与约束 |
| --- | --- |
| `backend/src/main.ts` | 命令行、旧 Go 排查、HTTP 与调度生命周期；父管道 EOF 触发退出 |
| `httpapi/router.ts` | Fastify 路由、流式上传、响应脱敏、Range/HEAD；不增加 API 鉴权 |
| `media/service.ts` | 工作流版本、素材逻辑删除、幂等入队、任务命令、事件与尝试事务 |
| `media/files.ts` | 512 MiB 上限、文件头、长度、哈希、临时文件与原子归档 |
| `scheduler/runner.ts` | 恢复、容量准入、一次性创建、查询、取消和下载退避 |
| `runninghub/client.ts` | HTTP 协议；不重试创建；不把自由文本、凭据与 URL 放入错误 |
| `storage/store.ts` | 兼容 v1 SQLite、同步事务、独立锁数据库 |
| `storage/legacy.ts` | 旧 Go 文件锁兼容检查，仅排查、不终止旧实例 |

后端运行库锁定 Fastify 5.12.3、multipart 9.3.0，不使用第三方原生 SQLite 扩展。Node 22.19 中内置 SQLite 仍会给出 experimental 提示，已在此实际版本运行测试。

前端不导入后端实现。公开类型从 OpenAPI 生成；后端内部类型单独扩展路径、账户摘要、上传快照及结果 URL。构建检查类型文件一致，测试检查公开 OpenAPI 路由全部注册。

## 数据与恢复

业务数据库仍为 media.sqlite，user_version=1；原有五张 JSON 实体表和 events 表不重建。Go 旧请求的字段顺序、缺省零值与 HTML 转义保留在请求指纹算法中，防止升级后重放请求重复入队。

`test/fixtures/go-v1.json` 由迁移前实际 Go Store/Service 生成，包含脱敏实体、事件与测试媒体的 Base64，没有账户密钥。测试重建旧数据库后关闭并重新打开，验证原批次、远端 ID、逻辑删除素材及事件保持兼容。原 Go 源码位于迁移前本地提交。

新实例以 node-service-lock.sqlite 独占事务保持运行权；进程退出自动释放。旧 service.lock 不提供新实例互斥能力。第一次切换必须先正常停止旧 Go；不能通过删除锁文件绕过仍在运行的旧服务。macOS 的旧进程排查实现尚未原生验收。

上传在容量检查前执行并逐项落库。提交先写 submitting，再发送一次请求；不确定响应进入 submission_unknown。存在远端 ID 的任务只查询或下载原任务。取消不覆盖迟到成功；全部结果归档后才成功。下载失败不增加生成尝试。

## 运行者切换步骤

1. 正常停止当前 DSH 和旧 Go 后端，确认退出；不要直接删除进程记录绕过活跃实例检查。
2. 在停机状态复制整个原 dataDir，包括媒体和配置；不能仅复制正在使用的 WAL 数据库主文件。
3. 已注册源码插件无需重新选择安装渠道。保留原 dataDir，移除曾手填的 binaryPath；默认使用包内 lib/backend.mjs。
4. 在 DSH 源码目录执行 `pnpm dsh web`。插件自动启动 Node 后端，健康接口应显示 runtime=node。
5. 检查历史素材、任务与 RunningHub 设置。未结束任务可能恢复远端查询；不要为了验证升级手动重试已有真实任务。

若需退回旧实现，先停止 Node，再使用迁移前代码或保留的 Go 包；恢复停机备份是最明确的回退方式。不要使回退数据库丢失新生成的远端任务 ID，否则需先人工核对。

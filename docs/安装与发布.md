# 安装与发布

## 用户安装

需要已安装的 DSH 和 Node ^22.19.0 或 >=24。Windows 已验收，macOS 尚未原生验收。

在 DSH 源码目录执行：

```powershell
pnpm dsh plugin --profile web add github:aidenli/dsh-atelier#dist
pnpm dsh web
```

全局安装 DSH 的用户将 `pnpm dsh` 换为 `dsh`。已有 DSH 进程需正常退出后重启。首次由 Go 升级需确认旧后端已停止，并在停机时备份完整数据目录。

插件自动启动内置 Node 服务，无需安装 Go、编译器或单独启动后端。在插件设置配置 RunningHub 密钥。安装不需要 npm 账号。

固定版本可将 `dist` 替换为该分支的完整提交 SHA；回退同样使用旧提交，并保留原 dataDir。main 是开发源码，不能作为直接安装入口。

## npm 状态

计划包名为 dsh-atelier，当前尚未发布。发布成功后支持：

```powershell
pnpm dsh plugin --profile web add dsh-atelier@0.3.1
```

维护者在 https://www.npmjs.com/signup 注册并验证邮箱，在账号设置启用双重验证，然后执行：

```powershell
npm login --registry=https://registry.npmjs.org
npm whoami --registry=https://registry.npmjs.org
```

密码、验证码、恢复码及令牌不写入仓库或聊天。

## 维护者发布

1. 设置 DSH_SOURCE，安装 frontend 和 backend 的锁定依赖。
2. 更新 plugin/package.json 版本；同一版本不可覆盖。
3. 执行下面的构建与验收，失败时停止发布。

```powershell
node scripts/pack-plugin.mjs
node scripts/check-archive.mjs dist/dsh-atelier-0.3.1-universal.tgz
node scripts/test-package.mjs dist/dsh-atelier-0.3.1-universal.tgz
node scripts/test-install.mjs dist/dsh-atelier-0.3.1-universal.tgz
node scripts/stage-distribution.mjs
```

stage-distribution 输出由同一个已校验 TGZ 解出的目录。更新 dist 时，在独立 clone 的 dist 分支中以该目录内容替换旧的受版本控制文件，检查清单后正常提交和推送，不强制推送，不混入源码和运行配置。记录 main 源码提交、dist 产物提交及 TGZ SHA256。

```powershell
node scripts/test-install.mjs github:aidenli/dsh-atelier#dist
npm publish dist/dsh-atelier-0.3.1-universal.tgz --access public --registry=https://registry.npmjs.org
node scripts/test-install.mjs dsh-atelier@0.3.1
```

npm 直接发布已测试 TGZ，不在 plugin 目录重新运行 publish，避免重新构建不同产物。交互验证由维护者本人完成。后续自动发布可另行配置 npm trusted publishing。

Release 备用包上传同一 TGZ 和相邻 .sha256 文件；不要覆盖旧 Go 版 0.3.0 草稿。当前未上传 Node Release。
